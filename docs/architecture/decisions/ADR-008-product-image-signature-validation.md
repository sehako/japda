# ADR-008: 상품 이미지 최초 등록 검증을 파일 시그니처로 제한

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-10

## 결정

상품 이미지 최초 등록 API는 새로운 외부 이미지 라이브러리를 추가하지 않고 JPEG, PNG, WebP의 파일 시그니처까지만 검사한다. 파일 개수, 빈 파일, 개별·합계 크기와 대표 이미지 지정은 함께 검증하되 이미지 전체 디코딩, 내부 데이터 손상 여부와 압축 해제 과정의 자원 사용은 검사하지 않는다.

검증에 통과한 파일의 미디어 타입은 확장자나 클라이언트가 보낸 `Content-Type`이 아니라 서버가 확인한 파일 시그니처로 결정한다. 시그니처가 정상이지만 내부 데이터가 손상된 파일이 등록될 수 있다는 한계를 허용한다.

정밀 무결성 검증, 디코딩 자원 제한과 이를 위한 외부 라이브러리 선택은 별도 후속 이슈에서 다룬다. 이 결정은 ADR-006에서 `infrastructure/image`에 이미지 디코더를 배치하기로 한 전제를 대체하며, ADR-006의 상품 이미지 패키지 구조 결정은 유지한다.

## 이유

이번 기능의 우선 목적은 판매자 상품 이미지 원본을 S3에 등록하고 메타데이터 저장과 상품 준비 상태를 일관되게 전환하는 것이다. JPEG와 PNG뿐 아니라 WebP까지 동일한 수준으로 완전히 디코딩하려면 추가 라이브러리 선정과 자원 제한 검토가 필요하므로 최초 등록 범위와 분리한다.

파일 시그니처 검사는 외부 라이브러리 없이 지원 형식을 구분하고 클라이언트가 보낸 확장자와 미디어 타입을 신뢰하지 않게 하는 최소 방어를 제공한다.

## 트레이드오프

파일 시그니처만 위조하거나 내부 데이터가 손상된 파일도 등록될 수 있다. 이미지 조회나 후속 처리 시점에 디코딩 실패가 발견될 수 있으며, 이번 API의 성공이 이미지 전체의 무결성을 보장하지 않는다.

정밀 검증을 후속 작업으로 미루므로 해당 기능이 도입될 때 기존 저장 이미지의 처리 정책과 등록 실패 계약을 다시 검토해야 한다.
