# ADR-006: 판매 영속성 경계와 기간 중첩 방지

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-09

## 결정

`Sale`은 `Product`와 JPA 연관관계를 만들지 않고 `productId`와 데이터베이스 외래 키로 상품을 참조한다. 상품 소유자의 단일 출처는 `Product.sellerId`로 유지하므로 `Sale`에는 `sellerId`를 중복 저장하지 않는다.

판매 상태는 저장하지 않고 현재 시각, 판매 시작·종료 시각과 잔여 수량으로 `SCHEDULED`, `ON_SALE`, `SOLD_OUT`, `ENDED` 중 하나를 계산한다. 판매 기간은 시작 시각을 포함하고 종료 시각을 제외하는 `[startsAt, endsAt)` 구간으로 해석한다.

같은 상품의 판매 기간 중첩은 PostgreSQL `btree_gist` 확장과 exclusion constraint로 방지한다. 애플리케이션의 사전 조회에 의존하지 않고 데이터베이스 제약을 순차 요청과 동시 요청의 최종 무결성 경계로 사용한다.

## 이유

도메인 사이를 ID로 참조하면 판매 조건과 상품 카탈로그의 결합을 줄이면서 외래 키로 참조 무결성을 유지할 수 있다. 판매자와 상태를 중복 저장하지 않으면 상품 소유권 변경이나 시간 경과에 따라 서로 다른 값이 생길 가능성을 없앨 수 있다.

기간 중첩을 애플리케이션 조회와 저장으로만 검사하면 동시 요청 사이의 경쟁 조건을 막을 수 없다. PostgreSQL의 범위 연산과 exclusion constraint를 사용하면 인접한 기간은 허용하면서 실제 중첩은 데이터베이스에서 원자적으로 거부할 수 있다.

## 트레이드오프

판매 응답에 판매자 정보가 필요하면 `Product`를 별도로 조회해야 하고, 상태 조건으로 검색할 때는 현재 시각과 판매 데이터를 사용한 쿼리가 필요하다. `Sale`에서 객체 연관관계를 탐색할 수 없으므로 여러 도메인의 조립은 Application 계층이 담당한다.

배포 PostgreSQL에 `btree_gist` 확장을 생성할 권한이 필요하다. 판매 취소나 일정 수정 기능을 추가할 때는 보존할 판매 데이터와 exclusion constraint 적용 조건을 다시 결정해야 한다.
