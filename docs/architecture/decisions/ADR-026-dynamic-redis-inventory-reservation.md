# ADR-026: 짧은 수명의 동적 Redis 재고 선점 계층 도입

- 상태: 대체됨 ([ADR-029](ADR-029-redis-sold-out-marker.md))
- 적용 영역: backend
- 결정일: 2026-09-16

## 결정

주문이 발생한 판매 일정의 가용 재고만 Redis에 동적으로 적재하고, Single-flight 초기화와 Lua script의 원자적 재고 선점으로 집중되는 주문 요청을 먼저 처리한다. Redis가 재고 부족을 반환하면 주문 API는 DB transaction을 시작하지 않고 즉시 품절로 응답한다.

Redis 재고는 초기화 시점부터 고정 30초 동안 유지하며 주문 요청으로 TTL을 연장하지 않는다. 같은 판매 일정의 cache miss가 몰리면 애플리케이션 인스턴스 내부에서 초기화 결과를 공유하고, 여러 인스턴스 사이에서는 짧은 Redis 초기화 lock으로 DB snapshot 생성을 하나로 제한한다.

Redis는 보조 선점 계층으로 한정한다. 기존 판매 일정 비관적 잠금, 주문 예약 집계와 DB 최종 재고 검증을 유지한다. Redis 연결 실패, timeout, script 오류와 초기화 실패는 기존 DB 주문 경로로 우회한다. Redis 선점 후 DB에서 신규 주문이 생성되지 않으면 세대가 일치하는 예약만 Lua script로 멱등하게 복원한다.

별도 DB 예약 테이블, 복구 배치와 비관적 잠금 제거는 이번 결정에 포함하지 않는다. 해당 기능이 도입되기 전에는 Redis를 영구적인 재고 원천으로 사용하지 않는다.

## 이유

한정판 판매에서는 일부 판매 일정에만 짧은 시간 동안 주문이 집중될 수 있다. 모든 판매 재고를 Redis에 상시 적재하면 사용되지 않는 데이터와 동기화 비용이 생기므로 실제 주문이 발생한 판매 일정만 짧게 활성화한다.

기존 ADR-015의 판매 일정 잠금과 주문 집계는 강한 정합성을 제공하지만 인기 판매 일정의 요청을 하나의 row lock에 직렬화한다. Redis Lua script로 품절 요청을 먼저 거절하면 품절 이후의 불필요한 DB 접근과 잠금 대기를 줄일 수 있다. Redis 예약에 성공한 요청은 기존 DB 검증을 계속 거치므로 Redis 재고가 과대 계산돼도 초과 판매로 이어지지 않는다.

DB 예약 영속화와 복구 장치가 없는 단계에서 장시간 Redis 재고를 유지하면 실패한 예약이나 주문 상태 변화로 정상 주문을 오래 거절할 수 있다. 고정 30초 TTL과 비연장 정책으로 잘못된 과소 재고의 영향을 제한하고, 만료 후 DB의 유효 예약 집계를 기준으로 다시 초기화한다.

## 트레이드오프

Redis 선점 후 DB 결과 반영 전에 프로세스가 종료되거나 주문 상태 변화가 즉시 반영되지 않으면 실제보다 적은 Redis 재고가 최대 30초 동안 유지될 수 있다. 이 기간에는 판매 가능한 재고가 있어도 품절로 응답할 수 있다.

처리 중인 주문이 DB에 commit되기 전에 Redis 재고가 만료되면 다음 초기화 snapshot이 해당 주문을 보지 못할 수 있다. 이때 일부 요청이 Redis를 통과하지만 기존 DB 비관적 잠금과 최종 예약 집계가 초과 판매를 막는다.

짧은 TTL 때문에 인기 판매 일정은 약 30초마다 DB snapshot 조회가 필요하다. Single-flight가 같은 판매 일정의 동시 초기화를 하나로 제한하지만 cache miss 시의 지연 자체는 없애지 못한다.

Redis와 Lua script, 장애 우회 및 보상 경로가 추가되어 주문 application과 운영 관측의 복잡도가 증가한다. 대신 Redis 장애가 주문 기능 전체의 장애가 되지 않고, DB가 최종 정합성 기준으로 남는다.
