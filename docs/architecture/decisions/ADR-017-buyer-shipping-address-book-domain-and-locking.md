# ADR-017: 구매자 배송지 목록 도메인과 잠금 행 구성

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-12

## 결정

사용자가 반복해서 사용하는 저장 배송지는 주문의 배송지 스냅샷과 분리된 `shippingaddress` 도메인에서 관리한다. 주문은 저장 배송지 Entity를 참조하지 않고 기존처럼 주문 생성 요청에 포함된 배송 정보를 자신의 값으로 보존한다.

구매자별 배송지 목록을 나타내는 `buyer_shipping_address_books`와 개별 배송지를 저장하는 `buyer_shipping_addresses`를 분리한다. book은 내부 생성 ID를 PK로 가지고 임시 외부 구매자 식별자인 `buyer_id`를 unique 값으로 저장한다. 배송지는 `buyer_shipping_address_book_id` FK로 book을 참조하며 `buyer_id`를 중복 저장하지 않는다.

구매자별 최대 10개 등록 규칙은 book 행의 비관적 쓰기 잠금으로 보장한다. 등록 트랜잭션은 구매자 book을 `INSERT ... ON CONFLICT DO NOTHING`으로 생성한 뒤 `buyer_id`로 해당 행을 잠그고, 배송지 개수와 배송지명 중복을 확인한 다음 배송지를 저장한다. `(buyer_shipping_address_book_id, address_name)` unique 제약으로 배송지명 중복을 최종 차단한다.

## 이유

저장 배송지는 사용자가 조회·수정·삭제하거나 주문마다 다시 선택할 수 있는 원본인 반면, 주문 배송지는 주문 당시 수취·배송 정보를 보존해야 하는 스냅샷이다. 두 모델을 직접 연결하면 저장 배송지 변경이나 삭제가 주문 이력에 영향을 줄 수 있으므로 생명주기와 도메인 경계를 분리한다.

현재 구매자 테이블이 없으므로 배송지 행이 외부 `buyer_id`를 직접 반복 참조하는 대신 book이 외부 식별자와 내부 목록의 연결을 담당한다. 향후 실제 구매자 도메인이 추가되면 book의 소유자 연결만 재검토할 수 있다.

단순히 개수를 조회한 뒤 저장하면 같은 구매자의 동시 요청이 모두 제한을 통과해 10개를 초과할 수 있다. 모든 등록이 같은 book 행을 먼저 잠그면 개수 확인과 저장을 직렬화하면서 서로 다른 구매자의 요청은 독립적으로 처리할 수 있다. 별도 개수 카운터를 저장하지 않아 동기화 상태도 추가하지 않는다.

## 트레이드오프

배송지 등록 API 하나를 위해 book 테이블과 upsert·잠금 흐름이 추가된다. 대신 최대 개수 규칙을 강하게 보장하고 향후 목록 단위 정책을 둘 명확한 경계를 제공한다.

같은 구매자의 배송지 등록은 하나의 book 행 잠금에 직렬화된다. 사용자별 최대 10개인 현재 범위에서는 처리량 영향이 제한적이지만, 대량 쓰기 요구가 생기면 잠금 전략을 다시 검토해야 한다.

배송지 개수를 매번 집계하므로 카운터 조회보다 비용이 들 수 있다. 현재 최대 행 수가 10개로 고정되어 있어 단순성과 정합성을 우선하며, 실제 부하가 별도 카운터를 정당화할 때 새로운 결정으로 검토한다.

실제 구매자 Entity와 FK를 아직 두지 않으므로 `buyer_id`의 존재 여부는 보장하지 않는다. 인증 및 구매자 도메인이 도입되면 소유자 식별과 참조 무결성을 별도로 설계한다.
