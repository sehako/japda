# ADR-005: 상품 이미지를 AWS S3에 저장

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-09

## 결정

상품 이미지 원본은 비공개 AWS S3 버킷에 저장하고 PostgreSQL에는 이미지 메타데이터와 S3 `objectKey`만 저장한다. 백엔드는 multipart 파일을 받아 S3에 업로드하며, AWS SDK 구현은 애플리케이션과 도메인이 직접 의존하지 않는 객체 저장소 인터페이스 뒤에 둔다. Kubernetes workload는 AWS 기본 credential provider chain을 통해 자격 증명을 얻는다.

## 이유

백엔드는 Kubernetes에서 여러 파드로 실행될 예정이므로 파드별 로컬 파일시스템은 파드 간 파일 공유와 재생성 후 지속성을 보장하지 못한다. RWX PersistentVolume은 공유 파일시스템의 가용성, 백업과 용량 확장을 애플리케이션 운영 범위에 추가한다. S3는 파드 수명과 이미지 수명을 분리하고 모든 인스턴스에 동일한 객체 저장소를 제공한다.

DB에 전체 URL 대신 `objectKey`를 저장하면 버킷, 리전과 향후 CloudFront 같은 전달 계층을 데이터 모델에서 분리할 수 있다. 백엔드가 업로드를 중계하면 현재 인증·소유권 경계에서 파일 형식과 용량을 일관되게 검증할 수 있다.

## 트레이드오프

S3와 PostgreSQL은 하나의 트랜잭션으로 묶을 수 없으므로 부분 업로드와 DB 실패에 대한 보상 삭제가 필요하다. 보상 삭제도 실패하면 고아 객체가 남을 수 있어 식별 가능한 로그, cleanup 대상 태그와 해당 태그에만 적용되는 S3 Lifecycle 정책이 필요하다. 백엔드가 파일을 중계하므로 presigned URL 직접 업로드보다 네트워크와 메모리·임시 파일 부하가 크다. AWS SDK dependency, 버킷 설정, workload identity와 IAM 운영 구성이 추가되며 실제 AWS 연동은 별도 환경 검증이 필요하다.
