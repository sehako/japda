# ADR-019: 결제 시도 기록과 주문 예약의 정합성

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-13

## 결정

한 주문에 하나의 `Payment` 시도를 저장하고, 첫 토스 승인 요청 전에 서버 생성 멱등키와 `CONFIRMING` 상태를 커밋한다. 결제 승인과 재확인은 토스 HTTP 호출 전후에 짧은 트랜잭션을 사용하며, 판매 일정 행을 먼저 잠근다. 검증된 `DONE`에만 `Payment.APPROVED`와 `Order.PAID`를 같은 트랜잭션에서 확정한다.

재고 집계에는 `PAID` 주문, 미만료 결제 대기 주문, 만료 후에도 `CONFIRMING` 또는 `REVIEW_REQUIRED`인 주문을 포함한다. 확정 실패한 `Payment.FAILED`는 예약에서 제외한다. 불명확한 결제는 저장된 멱등키로 자동 재확인하며, 결론이 없으면 수동 확인 상태로 전이하고 예약을 유지한다. `Payment`는 주문 ID만 참조한다.

## 이유

토스 승인 결과가 불명확하거나 승인 직후 서버가 중단되더라도 같은 시도를 재확인할 수 있어야 한다. 승인 중 예약이 만료되어 재고가 다시 판매되면 결제 완료 주문과 판매 수량의 정합성이 깨진다. 주문 상태와 결제 시도 상태를 분리하면 결제 실패를 주문 상태에 중복 기록하지 않고도 예약 해제 여부를 결정할 수 있다.

## 트레이드오프

불명확하거나 수동 확인이 필요한 결제는 운영자가 결론을 낼 때까지 판매 가능 수량을 점유한다. 주문 생성과 결제 확정이 같은 판매 일정 잠금에 직렬화되고, 예약 집계에서 결제 행도 조회하므로 처리량과 조회 비용이 증가한다. 한 주문에 새로운 결제 인증으로 재시도하려면 새 주문을 만들어야 한다.
