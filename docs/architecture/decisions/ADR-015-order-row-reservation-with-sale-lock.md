# ADR-015: 주문 행 기반 재고 예약과 판매 일정 잠금

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-11

## 결정

단일 상품 주문에서 `orders` 행을 결제 대기 중 재고 예약 기록으로 사용한다. 주문은 `PENDING_PAYMENT` 상태와 `expires_at`을 저장하며, 현재 시각보다 만료 시각이 늦은 주문만 유효한 예약으로 집계한다. 별도 재고 카운터나 예약 테이블은 두지 않는다.

주문 생성은 대상 `sales` 행에 비관적 쓰기 잠금을 획득한 뒤 같은 판매 일정의 유효한 예약 수량을 합산하고, `Sale.quantity`와 비교해 주문 가능 여부를 판단한다. 같은 판매 일정의 모든 주문 생성은 이 잠금 순서를 따라 동시 요청에서도 예약 수량 합계가 최초 판매 수량을 넘지 않게 한다.

`Order`는 `Sale` Entity와 JPA 연관관계를 맺지 않고 `saleId`로 참조한다. 주문 application이 `sale`과 `product` 도메인의 Repository를 호출해 판매 가능 여부, 가격과 상품명을 확인한다. `sale`과 `product` 도메인은 `order`를 의존하지 않는다.

예약 해제의 정확성은 Scheduler나 주문 상태 갱신이 아니라 `expires_at` 비교로 보장한다. 향후 결제 승인·실패, 취소와 만료 상태 정리가 추가되면 같은 판매 일정 잠금과 주문 상태 전이 규칙 안에서 확장한다.

## 이유

현재 주문은 `Sale` 하나만 참조하고 3분 동안 결제를 기다리는 제한된 기능이다. 주문 행에는 예약 주체, 수량, 상태와 만료 시각이 이미 있으므로 별도 예약 행은 같은 사실을 중복 표현한다.

판매 일정 행을 잠근 뒤 예약을 집계하면 별도 카운터 없이도 재고 확인과 주문 저장 사이의 경쟁 조건을 막을 수 있다. 만료된 주문은 시간 조건으로 즉시 제외되므로 예약 반환을 위한 상태 변경이나 Scheduler 실행에 의존하지 않는다. 서로 다른 판매 일정은 다른 행을 잠그므로 독립적으로 주문할 수 있다.

주문이 판매 일정과 상품을 ID로 참조하고 application이 흐름을 조율하는 구조는 상품 원본과 판매 일정을 분리한 ADR-009의 경계 원칙을 유지한다.

## 트레이드오프

주문 생성마다 해당 판매 일정의 유효한 주문 수량을 집계하므로 주문량이 매우 커지면 카운터 방식보다 조회 비용이 커질 수 있다. 유효 상태와 만료 시각을 대상으로 한 인덱스로 현재 범위의 비용을 제한하고, 실제 부하가 이를 정당화할 때 별도 재고 모델을 검토한다.

인기 판매 일정의 주문 생성은 하나의 `sales` 행 잠금에 직렬화되므로 처리량 상한이 생긴다. 대신 현재 규모에서 이해하기 쉽고 강한 정합성을 제공한다. 높은 처리량이나 복수 상품 원자 예약이 필요해지면 잠금 순서, 재고 카운터 또는 별도 예약 모델을 새 ADR로 결정한다.

만료된 주문의 상태가 자동으로 `EXPIRED`로 변경되지는 않는다. 이번 API는 주문 생성만 제공하며 예약 유효성은 `expires_at`으로 정확히 판단한다. 주문 조회, 운영 정리 또는 결제 연동에서 명시적 만료 상태가 필요해질 때 상태 전이와 정리 작업을 별도로 설계한다.
