# ADR-009: 상품 원본과 판매 일정의 도메인 경계 분리

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-10

## 결정

`Product`는 상품 기본 정보, 소유자와 판매 준비 상태를 관리하고, `Sale`은 상품 ID를 참조하여 판매일·가격·판매 수량을 관리한다. `SaleDay`는 판매 영역 안에서 판매일별 정원과 확보된 자리 수를 관리한다.

이미지 등록 기능이 상품을 `READY`로 전환한다. 판매 등록 application은 상품 domain Repository를 통해 소유권과 준비 상태를 확인하며, 판매 Entity는 상품 Entity나 이미지 저장소에 의존하지 않는다. 판매 등록으로 상품 상태를 변경하지 않는다.

이번 기능은 판매 일정 등록만 구현한다. 조회, 취소, 재등록, 재고 차감은 별도 기능으로 확장한다. 판매일별 행 잠금과 정원 관리는 판매 영역 내부의 구현으로 두며 공통 잠금 모듈로 확장하지 않는다.

## 이유

PRD와 기존 상품 등록 설계는 같은 상품을 여러 날짜와 가격으로 반복 판매하도록 요구한다. 상품 준비 상태와 개별 판매 조건의 생명주기를 분리하면 상품 원본을 재사용하면서 판매 일정별 제약을 독립적으로 검증할 수 있다.

상품에 가격·수량·판매일을 직접 추가하면 반복 판매마다 과거 조건을 덮어쓰거나 상품 원본을 복제해야 한다. 판매 Entity가 이미지나 상품 상태 전환까지 소유하면 이미지 등록과 판매 일정의 책임이 결합된다.

## 트레이드오프

판매 등록은 상품 조회와 판매 영역 저장을 조율해야 하며 상품 이미지 기능의 `READY` 계약이 선행 조건이 된다. 상품의 판매 준비 상태 의미를 변경할 때는 판매 등록 조건도 함께 검토해야 한다.

판매일별 자리 수는 판매 일정 수와 일치하도록 같은 트랜잭션으로 관리해야 한다. 향후 취소를 추가하면 자리 반환과 판매자 유일성 제약을 함께 변경하고 검증해야 한다. 현재 기능에 후속 상태와 API를 미리 추가하지 않아 검증 범위를 등록으로 제한한다.
