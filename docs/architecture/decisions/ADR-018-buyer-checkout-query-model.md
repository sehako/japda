# ADR-018: 구매자 체크아웃을 주문 영역의 조회 전용 모델로 구성

- 상태: 승인
- 적용 영역: backend
- 결정일: 2026-09-13

## 결정

단일 판매 상품의 체크아웃은 `order` 영역의 조회 전용 application 서비스가 조율한다. `order.domain.repository`에 영속성 기술에 독립적인 조회 계약과 결과 타입을 두고, infrastructure가 `sales`, `products`, 대표 `product_images`, 구매자의 `buyer_shipping_address_books`, `buyer_shipping_addresses`를 단일 읽기 쿼리로 결합한다. application은 결과를 예상 총액과 HTTP 응답용 값으로 조립한다.

배송지 소유자는 book의 `buyer_id`로 한정한다. 상품과 대표 이미지의 불변식 위반은 내부 데이터 오류로 처리하며, 판매 일정이 없는 경우만 404로 처리한다. 조회는 주문 생성, 예약 수량 집계, 행 잠금과 데이터 변경을 수행하지 않는다.

## 이유

체크아웃 화면에는 판매 정보와 구매자 저장 배송지가 함께 필요하다. 조회 전용 결과로 조합하면 쓰기 Entity 사이에 연관관계를 추가하지 않고 한 번의 조회로 필요한 값을 얻을 수 있다. book을 통해 배송지 소유권을 확인하므로 다른 구매자의 주소가 섞이지 않는다.

## 트레이드오프

조회 쿼리가 여러 도메인의 테이블 구조와 대표 이미지 불변식에 의존하므로 스키마나 정책 변경 시 함께 수정해야 한다. 체크아웃 응답은 조회 시점의 예상 정보이며, 판매 기간과 예약 수량을 검증하지 않아 주문 생성 성공을 보장하지 않는다.
