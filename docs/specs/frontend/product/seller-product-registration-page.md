# 판매자 상품 등록 페이지 설계

## 목적과 완료 조건

판매자가 하나의 화면에서 상품 기본 정보와 이미지를 입력하고, 기존 백엔드 API를 순차 호출해 상품을 `READY` 상태로 등록할 수 있는 프론트엔드 페이지를 제공한다.

다음 조건을 모두 만족하면 완료된 것으로 본다.

- 개발 설정에서 주입한 판매자 식별자를 상품 생성과 이미지 등록 요청의 `X-Seller-Id` 헤더에 전달한다.
- 유효한 상품명, 선택적인 설명, 이미지 1~10장과 대표 이미지 한 장을 입력할 수 있다.
- 상품 기본 정보 생성에 성공한 뒤 생성된 상품 식별자로 이미지 등록 API를 호출한다.
- 상품 기본 정보 생성에 실패하면 이미지 등록 API를 호출하지 않는다.
- 이미지 등록에 실패하면 같은 화면에서 상품 기본 정보를 중복 생성하지 않고 이미지 등록만 재시도할 수 있다.
- 백엔드의 `ProblemDetail` 오류를 폼 필드 또는 화면 수준 오류로 표시한다.
- 제출 중 입력 변경과 중복 제출을 방지한다.
- 모바일과 데스크톱에서 사용할 수 있으며 키보드와 보조 기술로 주요 입력과 오류를 인식할 수 있다.
- 프론트엔드 lint와 build가 통과한다.

## 기존 구조와 계약

프론트엔드는 `apps/frontend`의 Vite, React, TypeScript, TailwindCSS 구성을 사용한다. [프론트엔드 아키텍처](../../../architecture/frontend.md)의 `app → pages → features → shared` 의존 방향과 [디자인 지침](../../../DESIGN.md)의 monochrome commerce interface를 따른다.

화면을 구현할 때는 [판매자 상품 등록 HTML 목업](../../../mockups/seller-product-registration.html)을 기준 디자인으로 참고한다. 레이아웃, 여백, 색상, 타이포그래피, 반응형 전환과 이미지 선택 상태의 시각 표현은 목업을 우선 반영한다. 목업의 JavaScript는 상호작용을 시연하기 위한 코드이므로 애플리케이션 구조로 그대로 옮기지 않고, 이 문서에 정의된 feature 구조와 API 흐름에 맞춰 구현한다. 목업과 이 문서의 동작 또는 API 요구사항이 충돌하면 이 문서를 우선한다.

백엔드는 상품 등록을 두 단계로 제공한다.

1. `POST /api/products`가 상품명과 선택적인 설명을 받아 `DRAFT` 상품을 생성한다.
2. `POST /api/products/{productId}/images`가 이미지 묶음과 대표 이미지 정보를 받아 상품을 `READY`로 전환한다.

프론트엔드는 두 API를 하나의 사용자 등록 흐름으로 조율하되, 상품과 이미지의 백엔드 계약이나 생명주기를 변경하지 않는다. 관련 백엔드 계약은 [상품 기본 정보 등록 API 설계](../../backend/product/seller-product-registration-api.md)와 [상품 이미지 최초 등록 API 설계](../../backend/product/seller-product-image-registration-api.md)를 따른다.

## 페이지와 화면 구성

페이지 경로는 `/seller/products/new`, 페이지 컴포넌트 이름은 `SellerProductRegistrationPage`로 한다. 라우팅 라이브러리를 새로 도입하지 않으므로 현재 애플리케이션 진입점에서 이 페이지를 렌더링한다. 후속 기능에서 여러 페이지가 필요해질 때 라우터 도입을 별도로 결정한다.

화면은 다음 영역으로 구성한다.

1. 상단
   - 서비스 맥락을 나타내는 `JAPDA SELLER`
   - 페이지 제목 `상품 등록`
   - 상품 기본 정보와 대표 이미지를 등록한다는 간단한 안내
2. 이미지 등록
   - JPEG, PNG, WebP 이미지 1~10장 선택
   - 파일당 최대 10MiB, 전체 최대 50MiB 안내
   - 선택 순서에 따른 이미지 미리보기
   - 대표 이미지 지정과 개별 이미지 제거
3. 기본 정보
   - 필수 상품명과 100자 제한
   - 선택적인 상품 설명과 3000자 제한
   - 각 텍스트 입력의 현재 글자 수
4. 하단 액션
   - 보조 액션 `취소`
   - 주요 액션 `상품 등록`
   - 제출 중 상태 `등록 중...`

데스크톱에서는 이미지와 기본 정보 영역을 2열로 배치하고 모바일에서는 세로로 배치한다.

```text
┌──────────────────────────────────────────────────┐
│ JAPDA SELLER                         상품 등록    │
├───────────────────────┬──────────────────────────┤
│ 이미지 선택            │ 상품명 *                 │
│                       │ [                      ] │
│ ┌─────┐ ┌─────┐       │                          │
│ │대표 │ │     │       │ 상품 설명                │
│ └─────┘ └─────┘       │ [                      ] │
│                       │ [                      ] │
│ + 이미지 추가          │                          │
├───────────────────────┴──────────────────────────┤
│                               취소  [ 상품 등록 ] │
└──────────────────────────────────────────────────┘
```

흰 배경, 검정 CTA, 사각형 입력과 이미지 카드, 회색 경계선을 사용한다. 이미지가 가장 강한 시각 요소가 되도록 하고 장식용 accent color, gradient와 shadow는 사용하지 않는다. CTA에만 pill shape을 적용한다.

## 사용자 입력과 상태

폼 상태는 서버 상태와 분리해 등록 feature의 hook에서 관리한다.

| 상태 | 의미 |
| --- | --- |
| `name` | 상품명 원문 입력 |
| `description` | 상품 설명 원문 입력 |
| `images` | 선택 순서와 미리보기 URL을 포함한 이미지 목록 |
| `representativeIndex` | 현재 이미지 목록을 기준으로 한 대표 이미지의 0 기반 인덱스 |
| `createdProductId` | 기본 정보 생성 성공 후 이미지 재시도에 사용하는 상품 식별자 |
| `submissionStage` | 입력, 기본 정보 생성, 이미지 등록, 성공 단계 |
| `fieldErrors` | 필드별 검증 또는 서버 오류 |
| `formError` | 특정 필드에 속하지 않는 화면 수준 오류 |

이미지가 처음 한 장 추가되면 자동으로 대표 이미지로 지정한다. 대표 이미지가 삭제되면 남은 첫 번째 이미지를 대표 이미지로 지정한다. 대표 이미지보다 앞선 이미지가 삭제되면 실제 대표 이미지가 유지되도록 인덱스를 보정한다. 이미지 목록이 비면 대표 이미지 값도 제거한다.

미리보기에는 `URL.createObjectURL`을 사용한다. 이미지 제거, 전체 초기화와 컴포넌트 해제 시 더 이상 사용하지 않는 URL을 `URL.revokeObjectURL`로 해제한다.

## 개발용 설정

개발용 판매자 식별자는 Vite 환경 변수로 주입한다.

```env
VITE_SELLER_ID=1
```

API 기준 URL도 환경별 설정이 필요하면 다음 값을 사용한다.

```env
VITE_API_BASE_URL=http://localhost:8080
```

`shared/config/env.ts`가 `VITE_SELLER_ID`를 양의 정수로 검증하고 설정값을 노출한다. 값이 누락됐거나 정수가 아니거나 0 이하이면 제출 시 API를 호출하지 않고 개발 설정 오류를 표시한다. 판매자 식별자를 입력하거나 화면에서 변경하는 UI는 제공하지 않는다.

`VITE_*` 값은 브라우저 번들에 포함되므로 인증 정보나 비밀값으로 취급하지 않는다. `VITE_SELLER_ID`는 현재 백엔드의 임시 개발 계약에만 사용하고 실제 인증 도입 시 인증 principal 또는 세션 기반 흐름으로 교체한다.

## API 계약과 데이터 흐름

### 1단계: 상품 기본 정보 생성

```http
POST /api/products
X-Seller-Id: {VITE_SELLER_ID}
Content-Type: application/json
```

```json
{
  "name": "한정판 상품",
  "description": "선택적인 상품 설명"
}
```

상품명과 설명은 클라이언트 검증에 사용하는 정규화 결과와 백엔드 저장 결과의 의미가 일치하도록 앞뒤 공백을 제거해 전송한다. 설명이 공백뿐이면 `null`로 전송한다.

성공한 `201 Created` 응답에서 `id`와 `status: "DRAFT"`를 확인하고 `id`를 `createdProductId`에 저장한다. 응답 형식이 계약과 다르면 이미지 API를 호출하지 않고 화면 수준 오류를 표시한다.

### 2단계: 이미지 최초 등록

```http
POST /api/products/{productId}/images
X-Seller-Id: {VITE_SELLER_ID}
Content-Type: multipart/form-data; boundary=...
```

`FormData`에는 현재 화면 순서대로 각 파일을 `files` 이름으로 반복 추가하고 대표 이미지의 0 기반 인덱스를 `representativeIndex`로 추가한다. 브라우저가 multipart boundary를 생성하도록 프론트엔드에서 `Content-Type` 헤더를 직접 지정하지 않는다.

성공한 `201 Created` 응답에서 요청한 상품 식별자와 `status: "READY"`를 확인하고 등록 완료 상태를 표시한다.

전체 데이터 흐름은 다음과 같다.

```text
SellerProductRegistrationPage / UI
                ↓
useProductRegistration
                ↓
클라이언트 입력 검증
                ↓
createProduct API
                ↓ 201 Created / productId
registerProductImages API
                ↓ 201 Created / READY
등록 완료 상태
```

두 요청에 `AbortSignal`을 전달해 페이지 해제 시 진행 중인 요청을 취소할 수 있게 한다. 요청 취소는 사용자 오류로 표시하지 않는다.

## 프론트엔드 구조와 책임

```text
src/
├── app/
│   └── App.tsx
├── pages/
│   └── seller-product-registration/
│       └── SellerProductRegistrationPage.tsx
├── features/
│   └── product-registration/
│       ├── api/
│       │   └── productRegistrationApi.ts
│       ├── model/
│       │   └── productRegistration.ts
│       ├── hook/
│       │   └── useProductRegistration.ts
│       └── ui/
│           ├── ProductRegistrationForm.tsx
│           └── ProductImageField.tsx
└── shared/
    ├── api/
    │   └── apiClient.ts
    └── config/
        └── env.ts
```

- `SellerProductRegistrationPage`는 페이지 레이아웃과 feature 조합을 담당한다.
- `ProductRegistrationForm`은 텍스트 필드, 제출 액션과 오류 렌더링을 담당한다.
- `ProductImageField`는 파일 선택, 미리보기, 제거와 대표 이미지 지정을 담당한다.
- `useProductRegistration`은 폼 상태, 검증, 두 API의 순차 실행, 재시도와 제출 상태를 담당한다.
- `productRegistrationApi`는 상품 생성 JSON 요청과 이미지 multipart 요청을 담당한다.
- `apiClient`는 API 기준 URL 적용, 공통 응답 파싱과 `ProblemDetail` 변환을 담당한다.
- `env`는 개발용 판매자 식별자와 API 기준 URL 설정을 담당한다.

UI 컴포넌트에서 API를 직접 호출하지 않는다. 현재 dependency에 Query 또는 Form 라이브러리가 없고 단일 생성 흐름이므로 React 상태와 `fetch`를 사용하며 새로운 dependency를 추가하지 않는다.

## 클라이언트 검증

서버 요청 전에 다음 항목을 검증한다.

| 입력 | 검증 규칙 |
| --- | --- |
| 상품명 | `trim()` 결과 1자 이상 100자 이하 |
| 상품 설명 | `trim()` 결과 최대 3000자, 공백뿐이면 `null`로 정규화 |
| 이미지 개수 | 1장 이상 10장 이하 |
| 이미지 형식 | 브라우저가 제공한 MIME type 기준 JPEG, PNG, WebP |
| 개별 이미지 크기 | 1바이트 이상 10MiB 이하 |
| 전체 이미지 크기 | 50MiB 이하 |
| 대표 이미지 | 현재 이미지 목록에 정확히 한 장 지정 |

브라우저의 MIME type 검사는 빠른 사용자 피드백만 제공한다. 파일 확장자와 클라이언트 MIME type은 신뢰할 수 없으므로 백엔드가 파일 시그니처를 최종 검증한다. 클라이언트 검증 통과가 서버 등록 성공을 보장하지 않는다.

검증 오류는 사용자가 수정할 수 있도록 해당 필드 가까이에 표시하고 첫 번째 오류 필드로 focus를 이동한다.

## 오류 처리와 재시도

`apiClient`는 `application/problem+json` 응답의 `code`, `detail`, `errors`를 파싱한 공통 오류 타입을 반환한다. 응답이 해당 형식이 아니거나 네트워크 요청 자체가 실패하면 일반 API 오류로 변환한다. 내부 예외, 응답 원문과 설정값을 화면에 노출하지 않는다.

오류는 다음 위치에 표시한다.

| 오류 속성 | 표시 위치 |
| --- | --- |
| `name` | 상품명 입력 아래 |
| `description` | 상품 설명 입력 아래 |
| `files` | 이미지 영역 아래 |
| `representativeIndex` | 이미지 영역 아래 |
| `sellerId` | 폼 상단 오류 배너 |
| `productId` 또는 속성 없음 | 폼 상단 오류 배너 |

백엔드 메시지가 있으면 이를 표시하고, 응답을 해석할 수 없으면 `상품을 등록하지 못했습니다. 잠시 후 다시 시도해 주세요.`를 표시한다.

상품 기본 정보 생성에 실패하면 `createdProductId`를 설정하지 않고 전체 제출을 다시 시도할 수 있게 한다. 기본 정보 생성 후 이미지 등록에 실패하면 서버에 `DRAFT` 상품이 남으므로 `createdProductId`를 현재 hook 상태에 유지한다. 사용자가 재시도하면 상품 기본 정보 API를 다시 호출하지 않고 이미지 등록 API만 호출한다.

재시도 대기 중에는 상품명, 설명과 이미지 목록을 잠가 서버의 `DRAFT` 상품과 재시도 데이터가 달라지는 것을 방지한다. 사용자가 입력을 변경하려면 현재 재시도 흐름을 포기하고 새 등록을 시작해야 하며, 서버에 기본 정보만 저장된 상품이 남을 수 있음을 확인 경고로 알린 뒤 로컬 상태만 초기화한다.

새로고침이나 페이지 이탈 뒤에는 `createdProductId`를 복구하지 않는다. 브라우저 저장소에 상품 식별자를 보관하면 오래된 임시 상태와 소유권 문제가 생기므로 이번 범위에서는 사용하지 않는다. 재시도 대기 중 이탈을 시도하면 `beforeunload` 경고를 등록하고, 해당 상태를 벗어나면 해제한다.

`409 PRODUCT_IMAGES_ALREADY_REGISTERED`는 이전 요청의 성공 여부를 조회할 API가 없어 성공으로 간주하지 않는다. `이미지가 이미 등록되었거나 이전 요청이 완료되었습니다. 상품 상태를 확인해 주세요.`라는 화면 수준 오류를 표시하고 추가 제출을 막는다.

## 제출과 완료 상태

제출 중에는 상품명, 설명, 이미지 변경, 취소와 제출 버튼을 비활성화해 중복 요청과 화면 상태 변경을 방지한다. 정확한 업로드 진행률은 제공하지 않고 `상품 정보를 저장하는 중`과 `이미지를 등록하는 중`으로 현재 단계를 표시한다.

이미지 등록 성공 후 별도의 상품 조회나 목록 API가 없으므로 존재하지 않는 화면으로 이동하지 않는다. 현재 페이지를 등록 완료 상태로 전환하고 다음 정보를 표시한다.

- `상품 등록이 완료되었습니다.`
- 생성된 상품 식별자
- 상품 상태 `READY`
- `새 상품 등록` 액션

`새 상품 등록`을 선택하면 폼과 미리보기 자원을 초기화하고 빈 등록 화면으로 돌아간다.

취소 액션은 기본 입력 상태에서는 입력값이 있으면 이탈 확인 후 폼을 초기화한다. 기본 정보가 생성된 재시도 상태에서는 `DRAFT` 상품이 남는다는 확인을 추가로 표시한다. 상품 삭제 API가 없으므로 취소가 서버 데이터를 삭제한다고 안내하지 않는다.

## 접근성

- 모든 입력에 화면에 보이는 `label`을 연결한다.
- 필드별 안내와 오류를 `aria-describedby`로 입력에 연결한다.
- 필수 필드와 유효하지 않은 필드에 각각 `required`, `aria-invalid`를 적용한다.
- 제출과 서버 오류 알림에 `role="alert"`를 적용한다.
- 제출 단계 안내에는 `aria-live="polite"`를 적용한다.
- 이미지 제거와 대표 지정은 키보드로 조작할 수 있는 버튼 또는 라디오 입력으로 제공한다.
- 미리보기 이미지 대체 텍스트에 파일명과 대표 여부를 포함한다.
- 이미지 선택 후 목록 변경과 검증 오류가 발생해도 focus를 예기치 않게 잃지 않도록 한다.

## 호환성과 제약

- `fetch`, `FormData`, `File`, `URL.createObjectURL`, `AbortController`와 `beforeunload`를 지원하는 현대 브라우저를 대상으로 한다.
- 프론트엔드와 백엔드 origin이 다르면 백엔드의 CORS 설정이 `X-Seller-Id`와 해당 origin을 허용해야 한다. 이는 현재 프론트엔드 구현 범위에서 변경하지 않는다.
- 백엔드가 이미지 접근 URL을 반환하지 않으므로 등록 완료 뒤 서버 이미지를 다시 조회하거나 표시하지 않는다.
- 백엔드에 상품 조회 API가 없으므로 응답 유실이나 `409` 발생 시 최종 상태를 자동 판정하지 않는다.
- 개발용 판매자 식별자 설정은 실제 인증을 제공하지 않는다.

## 검증 전략

현재 프론트엔드에 테스트 dependency와 테스트 script가 없으므로 이번 기능만을 위해 테스트 도구를 추가하지 않는다. 순수 검증 함수와 상태 전환 로직은 UI 및 hook에서 분리해 후속 테스트 환경 도입 시 단위 테스트할 수 있게 한다.

구현 후 다음을 확인한다.

- 상품명과 설명의 빈 값, 공백 정규화와 최대 길이 경계를 수동 검증한다.
- 이미지 1장과 10장, 빈 파일, 11장, 개별 10MiB와 전체 50MiB 경계를 검증한다.
- 이미지 추가와 삭제에 따라 대표 이미지 인덱스가 올바르게 유지되는지 검증한다.
- 두 요청에 동일한 개발용 `X-Seller-Id`가 전달되는지 확인한다.
- 상품 기본 정보 성공 후 반환된 `productId`가 이미지 요청 경로에 사용되는지 확인한다.
- `FormData`의 파일 순서와 `representativeIndex`가 화면 상태와 일치하는지 확인한다.
- 기본 정보 생성 실패 시 이미지 API가 호출되지 않는지 확인한다.
- 이미지 등록 실패 후 재시도에서 상품 기본 정보 API가 다시 호출되지 않는지 확인한다.
- 백엔드 `ProblemDetail`의 필드별 오류와 일반 오류가 지정한 위치에 표시되는지 확인한다.
- 제출 중 중복 요청과 입력 변경이 차단되는지 확인한다.
- 모바일과 데스크톱 레이아웃, 키보드 조작과 focus 이동을 확인한다.
- `npm run lint`와 `npm run build`를 실행한다.

## 주요 결정

- 백엔드의 분리된 상품 생성과 이미지 등록 계약을 유지하고 프론트엔드 hook이 두 요청을 순차 조율한다.
- 판매자 식별자는 화면 입력이 아니라 `VITE_SELLER_ID` 개발 설정에서 주입한다.
- 이미지 등록 실패 후 현재 화면에서는 생성된 상품 식별자를 유지해 이미지 요청만 재시도한다.
- 재시도 정보는 브라우저 저장소에 영속화하지 않는다.
- 등록 성공 후 이동할 조회·목록 API가 없으므로 현재 화면에서 완료 상태를 제공한다.
- 현재 범위에는 새로운 dependency를 추가하지 않는다.
